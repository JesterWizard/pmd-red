# ROM asset sizes

Sizes measured from the matching `pmd_red` build (`pmd_red.map` + `baserom.gba` / `pmd_red.gba`). The image is a fixed **32.00 MiB** GBA ROM (`0x08000000`–`0x09FFFFFF`).

Use this as a priority list for reclaiming space (recompression, stripping unused data, or replacing assets). Percentages are of the full 32 MiB image.

## Best compression / space-saving targets

Ranked by likely bytes recoverable for a hack ROM (not for matching the retail image).

### 1. Monster graphics — 17.68 MiB (first place to look)

- ~55% of the entire ROM.
- Already uses **AT4PX** heavily (~329 markers in the section) plus SIRO containers / portraits (`data/kao`).
- Further savings usually mean:
  - Fewer species / frames / shiny variants
  - Lower-detail sprites
  - Stronger or alternate compression (only if the loader is taught to understand it)
  - Deduplicating shared tiles/palettes

Source on disk: `graphics/ax/` (~15.3 MiB of PNG/4bpp intermediates) built into `src/monster_gfx*.c` + `monster_sbin`.

### 2. Ground maps — 4.45 MiB raw → 2.67 MiB modern

- Second-largest section.
- **No AT4PX** markers; stored as `pksdir0` archive entries (BMA/BPL/etc. style map data).
- All 677 payloads now have lossless LZ77 copies generated by `compress_ground_assets.py`.
- The modern build decompresses each file into EWRAM before the existing BPL/BPC/BMA/BPA parsers use it.
- Compression result: `4,652,176 → 2,801,556` bytes, saving `1,850,620` bytes (39.8%).
- The matching build continues to use the raw files, so `make compare` remains byte-identical.
- Built from `src/ground_map_files_*.c` / `ground_sbin`.

### 3. Unknown / unused blobs — ~2.36 MiB (possible free wins)

| Blob | Size | In-repo hint |
| --- | ---: | --- |
| `unk_9D02950` | 1.36 MiB | `data/unknown_unused/unk_9D02950.bin` |
| `unk_96BD7AC` | 0.51 MiB | `data/unk_96BD7AC.s` (raw baserom slice) |
| `unk_data_9FBD5D0` | 0.26 MiB | `data/unk_9fbd5d0.s` |
| `unk_98589A4` | 0.22 MiB | `data/unk_98589A4.s` |
| `unk_9E7EB08` | 5.2 KiB | `data/unk_9E7EB08.s` |

If runtime references can be proven dead (especially `unk_9D02950`), deleting them is cheaper than recompressing.

### 4. Sound — 1.24 MiB

- DirectSound-style wave samples under `sound/wave/` (~9 MiB *source* text/asm; ~1.24 MiB linked).
- Not AT4PX-compressed; large individual samples (several 100+ KiB source files).
- Savings: shorten samples, lower rate/bit depth, remove unused SFX/songs, or compress if you add a decode path.

### 5. Effect graphics — 1.10 MiB

- SIRO-wrapped (~147 SIRO) but **0 AT4PX**.
- Same opportunity as ground data: compress subfiles or drop unused effects.

### 6. Dungeon + system archives — 1.77 MiB combined

- Already AT4PX-rich (`dungeon_sbin` ~204, `system_sbin` ~387 markers).
- Less headroom than ground/effects unless you delete content (fonts, unused dungeon tilesets, level maps).

### 7. Code / tables — ~2.4 MiB

- `.text` ~0.71 MiB, `.rodata` ~1.72 MiB.
- Compressing executable code is usually not worth it on GBA; trimming unused systems or string/table data is the realistic approach.

## What is already compressed?

Retail PMD Red uses **AT4PX** (and related AT\*P\* formats handled by `DecompressAT` in `src/decompress_at.c`):

| Marker in baserom | Count |
| --- | ---: |
| `SIRO` | 1325 |
| `AT4PX` | 929 |
| `pksdir0` | 634 |

Rough AT4PX density by section:

| Section | AT4PX count | SIRO count |
| --- | ---: | ---: |
| `monster_sbin` | 329 | 496 |
| `system_sbin` | 387 | 392 |
| `dungeon_sbin` | 204 | 240 |
| `effect_sbin` | 0 | 147 |
| `ground_sbin` | 0 | 0 |
| `titlemenu_sbin` | 9 | 8 |
| `sound_data` | 0 | 1 |

**Takeaway:** monster/system/dungeon graphics are largely compressed already; **ground maps, effects, sound samples, and the unknown blobs are the main “still fat” areas.**

## Forced gaps (matching layout only)

The matching linker script pins some archives to fixed addresses, which leaves empty `0xFF` gaps (usable once the ROM is shiftable / rebuilt with `make modern`):

| Gap after | Approx. free |
| --- | ---: |
| `system_sbin` → `titlemenu_sbin` | ~51 KiB |
| `titlemenu_sbin` → `dungeon_sbin` | ~52 KiB |
| `dungeon_sbin` → `monster_sbin` | ~60 KiB |
| `unk_9E7EB08` → `sound_data` | (sound starts at `0x09E80000`) |
| Large `0xFF` runs elsewhere | ~0.7 MiB total |

These gaps do not help a matching retail build, but they matter when packing a modified ROM tightly.

## Source-tree sizes (not ROM sizes)

Unpacked repo assets are larger than the linked ROM sections (PNG intermediates, JSON, asm expansions):

| Tree path | On-disk size | Role |
| --- | ---: | --- |
| `graphics/ax/` | ~15.3 MiB | Monster sprite source (PNG/4bpp) |
| `sound/wave/` + `sound/songs/` | ~14.4 MiB | Samples + sequences (source form) |
| `data/` | ~22 MiB | Archives, JSON, dungeon data |
| `src/` | ~81 MiB | Includes huge generated `monster_gfx*.c` / map files |

Prefer the **ROM section table** above when deciding what saves space in `pmd_red.gba`.

## Quick “where do I start?” checklist

1. **Confirm whether `unk_9D02950` (~1.36 MiB) is truly unused**, then strip it.
2. **Investigate compressing `effect_sbin`** (~1.10 MiB, SIRO but no AT4PX).
3. **Trim or recompress monster sprites** only if you still need more — largest slice, but already AT4PX-heavy.
4. **Cut or downsample sound waves** if audio quality can drop.
5. After the ROM is shiftable, **repack with `make modern`** to eliminate forced address gaps.
